# Поездки: поезда, самолёты, отели, маркетплейс

Что здесь доводится до оплаты, а что нет:

| Вертикаль | Поиск | Оформление | Оплата | Возврат |
|---|---|---|---|---|
| Поезда | да | да | да | да |
| Самолёты | да | да (одним шагом с оплатой) | да | **нет в API банка** |
| Отели | да | нет | нет | нет |
| Маркетплейс | да | нет | нет | нет |

Про отели и маркетплейс говори прямо: «найти и сравнить можно, оформить —
только в приложении». Не обещай бронь, которой нет.

## Инструменты

| Тул | Что делает | Деньги |
|---|---|---|
| `train_calendar(origin, destination, limit)` | Даты в продаже; заодно дешёвая проверка пары кодов станций | нет |
| `train_search(origin, destination, date, adults, children, limit)` | Поиск поездов; печатает `train_id` | нет |
| `train_seats(train_id, car_type, max_price, limit)` | Вагоны и свободные места как «вагон/место» | нет |
| `train_book(train_id, seats, passengers)` | Бронь; держит места ~15 минут | нет |
| `train_pay(order_id, card_id)` | Оплата брони через T-Pay | **ДА** |
| `train_refund(order_id, ticket_ids, confirm)` | Расчёт возврата, а с `confirm=True` — сам возврат | возвращает |
| `flight_search(from_code, to_code, date, …)` | Поиск рейсов; печатает `offerId` | нет |
| `flight_offer(offer_id, fare)` | Тарифы по рейсу, багаж, правила возврата | нет |
| `flight_seats(offer_id, fare, max_price, limit)` | Карта мест с ценами (места платные) | нет |
| `flight_book(offer_id, fare, passengers, seats, account_id)` | Оформляет И оплачивает — одним вызовом | **ДА** |
| `hotel_search(query, checkin, checkout, adults, children, limit)` | Поиск отелей с ценами | нет |
| `hotel_info(hotel_id, checkin, checkout, …)` | Карточка, отзывы, тарифы и условия отмены | нет |
| `trips(trip_id)` | Поездки одной лентой; с аргументом — карточка | нет |
| `travel_payment_options(amount, account_id)` | Чем платить, бонусы, кэшбэк, рассрочка | нет |
| `travel_order_details(order_id)` | Детали заказа: вагон и места, маршрут, отель | нет |
| `travel_ticket_file(order_id, save_to, overwrite)` | Билет или маршрутную квитанцию в файл | нет |
| `flight_history()` | История авиапоисков — единственный источник кодов IATA с названиями | нет |
| `shop_search(query, limit, offset)` / `shop_cart(limit)` | Маркетплейс, read-only | нет |

## Поезд: от поиска до билета

1. Коды станций ЧИСЛОВЫЕ (2000000 — Москва, 2004000 — Петербург), резолвера
   «название → код» у банка нет. Если код неизвестен — `train_calendar(origin,
   destination)`: на неверной паре ответ пуст.
2. `train_search(origin, destination, date)` → поезда; каждая строка несёт
   `train_id`.
3. `train_seats(train_id)` → места как `03/10`. Фильтры: `car_type` («плац»,
   «купе»), `max_price`.
4. `train_book(train_id, seats="03/10,03/12", passengers="me")` → номер заказа,
   сумма и время, до которого держится бронь. Денег ещё не списано.
5. `train_pay(order_id)` **без карты** → список карт и счетов, которыми можно
   заплатить; ничего не списывается. Покажи список пользователю.
6. `train_pay(order_id, card_id="…")` → сумму подтверждает КНОПКА.

Возврат: `train_refund(order_id)` печатает, сколько вернут и сколько удержат
сборами, и НИЧЕГО не возвращает. Покажи расчёт, и только если пользователь
согласен — `train_refund(order_id, confirm=True)`.

## Самолёт: от поиска до билета

1. Кода IATA по названию города банк не резолвит — бери из `flight_history()`,
   не подставляй по памяти.
2. `flight_search(from_code, to_code, date)` → предложения; каждое несёт
   `offerId`. `only_bookable=True` (по умолчанию) — только то, что банк продаёт
   сам.
3. `flight_offer(offer_id)` → **тарифы**. Один рейс из выдачи — это семья
   тарифов: тот же борт, разный багаж и разные правила возврата. Покажи их
   пользователю: цену, багаж, возвратность. Здесь же цена пересчитывается.
4. `flight_seats(offer_id, fare)` — по желанию. Места платные; без них место
   дадут при регистрации.
5. `flight_book(offer_id, fare=N, passengers="me")` — **это сразу и бронь, и
   оплата**, отдельного шага брони у авиа нет. Сумму подтверждает кнопка.

⚠️ **Оплата авиабилета через MCP экспериментальная и ни разу не выполнялась.**
Запрос уходит без подписи, которую шлёт приложение; если шлюз её проверяет, тул
вернёт «ИСХОД НЕИЗВЕСТЕН». Предупреди пользователя и предложи надёжный путь —
приложение. Поиск, тарифы и места (шаги 1–4) — полноценные, ими можно пользоваться.

Если выбраны места, к цене прибавляется ещё и услуга регистрации — итог
считает сам тул и он же кладёт его на кнопку.

## Пассажиры

`passengers="me"` — владелец счёта; паспорт и латиница берутся из данных банка
(`documents()`), ничего вводить не нужно.

Несколько пассажиров — JSON-список, порядок соответствует порядку мест:

```json
[{"me": true},
 {"first": "Мария", "last": "Петрова", "middle": "Ивановна",
  "birthDate": "1992-02-02", "number": "1234567890", "sex": "female"}]
```

Для авиа можно добавить `"firstEn"`/`"lastEn"` и бонусную карту
`{"bonus_card": {"carrier_code": "SU", "number": "…"}}`. Спутников приходится
вводить руками: банк хранит документы одного контакта, и подставить туда
паспорт родственника молча — значит посадить в поезд не того человека.

## Отели

`hotel_search(query, checkin, checkout)` → отели с ценами и `hotel_id`;
`hotel_info(hotel_id, checkin, checkout)` → карточка, саммари отзывов, оценки и
тарифы с условиями отмены.

Если тул сказал, что выдача ещё догружалась, — не делай вывод «дешевле нет»,
повтори вызов. Забронировать через MCP нельзя.

## Ключевые правила

1. **Кнопка — единственное подтверждение денег.** `train_pay` и `flight_book`
   показывают её сами. Твоя работа — ДО вызова показать состав: поезд, вагон и
   места, или рейс, тариф, багаж и правила возврата. НЕ спрашивай «да/нет»
   текстом сверху: в клиенте с кнопками это двойной вопрос.
2. **Сумму называет тул, а не ты.** Цена в выдаче поиска устаревает; и
   `flight_book`, и `train_pay` берут её заново и кладут на кнопку свою.
3. **Возврата авиабилета нет.** В API банка есть только допуслуга
   «гарантированный возврат», которая покупается вместе с билетом. Не обещай
   отмену перелёта и не выдумывай тул.
4. **Коды не выдумывай** — станции из `train_calendar()`, IATA из
   `flight_history()`.
5. **Идентификаторы носи как есть.** `train_id`, `offer_id`, `order_id` —
   непрозрачные; передавай их дословно из предыдущего ответа. Если тул сказал,
   что поезд или место пропали, — не подставляй старое значение, повтори поиск.
6. **`train_book` держит места ~15 минут.** Если пользователь ушёл думать —
   бронь пропадёт сама, это нормально; не бронируй «про запас» второй раз.

## Когда исход платежа неясен

`train_pay` и `flight_book` могут вернуть НЕопределённый результат — запрос ушёл,
но подтверждения нет (для авиа это ещё и неподписанный путь, «ИСХОД НЕИЗВЕСТЕН»,
см. выше). Заказ при этом МОГ создаться.

1. **Повтор блокируется.** Тот же вызов второй раз тул отвергнет — чтобы не
   создать второй платёж по тому же заказу. Это защита, а не ошибка.
2. **Сначала проверь заказ, а не плати заново.** `trips()` и
   `travel_order_details(order_id)` (для авиа), билет — в приложении. Если заказ
   уже оплачен, `train_pay` так и скажет («уже оплачен») — не плати повторно.
3. **`force=True` — только с явного согласия пользователя**, что прошлого списания
   и заказа НЕТ. Сам force не подставляй: он снимает единственную защиту от двойной
   оплаты.
4. **Возврат ЖД.** Если `train_refund(order_id, confirm=True)` вернул неясный
   статус — не запускай его повторно; сверься через `travel_order_details(order_id)`,
   там виден фактический статус билета.
