# Оплата счетов через T-Bank MCP

> ⚠️ **Что реально умеет MCP.** Пополнение телефона — да, это обычный P2P-перевод.
> Оплата сервисных счетов (ЖКХ, интернет, налоги, штрафы, образование) — **нет**:
> тула для неё не существует. Не обещай пользователю оплату и не делай вид, что
> проводишь её. Честный ответ: посчитать комиссию, если знаешь id провайдера, и
> отправить платить в приложение.

## Инструменты

| Тул | Что делает |
|---|---|
| `list_accounts()` | Счета + балансы (выбрать, откуда платить) |
| `transfer(amount, to_account, description, from_account)` | Пополнение телефона (P2P). **Реальные деньги** |
| `payment_commission(body)` | Предпросмотр комиссии (БЕЗ денег) — нужен валидный id провайдера |
| `get_data("providers", ids)` | Найти провайдера **по известным id**. Перечислить всех нельзя |
| `get_data("invoices")` | Выставленные счета к оплате |
| `get_data("templates")` | Сохранённые шаблоны платежей — там лежат id провайдеров, которыми пользователь уже платил |
| `get_data("autopayments")` | Настроенные автоплатежи |

## Пополнение телефона — работает

**«Пополни телефон на 500»**

1. `list_accounts()` → выбрать счёт списания, спросить пользователя если их несколько.
2. Показать сумму и номер, дождаться подтверждения.
3. `transfer(500, "+7XXXXXXXXXX", "Пополнение", from_account="<счёт>")`

Внутри Т-Банка это бесплатный P2P. Дальше — как в скиле переводов
(`tbank-transfer-money`): те же правила подтверждения и та же обработка
«ИСХОД НЕИЗВЕСТЕН».

## Сервисные счета — только комиссия и приложение

**Id провайдера нельзя угадать.** Он выглядит как `fns-rf` (ФНС),
`gibdd-online-rf` (штрафы ГИБДД), `toll-roads-avtodor` (платные дороги) — это
проверенные по захвату значения. Эндпоинт `providers/compatible/filter`, за
которым стоит `get_data("providers", ids)`, умеет только **проверять известные
id**, а не выдавать список: без `ids` он возвращает пустоту.

Поэтому:

1. Посмотри `get_data("templates")` и `get_data("autopayments")` — если
   пользователь уже платил этому поставщику, id лежит там. Это единственный
   надёжный способ его получить.
2. Нашёл id → можешь показать комиссию:
   ```
   payment_commission({"payParameters": {
       "provider": "gibdd-online-rf",
       "account": "<счёт списания>",
       "moneyAmount": 750,
       "currency": "RUB",
       "paymentType": "Payment",
       "providerFields": {"<поля из шаблона>": "..."}
   }})
   ```
   `paymentType` здесь **обязателен** (для переводов — `"Transfer"`, для оплаты
   услуг — `"Payment"`). Не пиши `pointerType: "ACCOUNT"` — банк такое отвергает
   с `INVALID_REQUEST_DATA`.
3. Не нашёл id или пользователь платит впервые — скажи прямо, что через MCP
   оплату провести нельзя, и отправь в приложение. Не выдумывай id: платёж уйдёт
   не туда или не уйдёт вовсе.

## Правила

1. **Не обещай того, чего нет.** Оплата ЖКХ/налогов/штрафов через MCP не
   реализована — говори это сразу, а не после трёх уточняющих вопросов.
2. **Id провайдера — только из шаблонов/автоплатежей или от пользователя.**
   Угаданный id хуже отсутствия id.
3. **Комиссия до подтверждения, подтверждение до денег.** Просьба «оплати» —
   это запрос, а не подтверждение.
4. **Сумму не угадывай** — спроси или возьми из `get_data("invoices")`.
5. **Пополнение телефона идёт как перевод** — со всеми правилами
   `tbank-transfer-money`, включая `from_account`.
