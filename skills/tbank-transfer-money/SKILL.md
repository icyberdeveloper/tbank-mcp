# Переводы через T-Bank MCP

## Инструменты

| Тул | Что делает |
|---|---|
| `list_accounts()` | Список счетов пользователя (источник) |
| `account_requisites(account_id)` | Реквизиты счёта (номер, БИК) — чтобы ПРИНЯТЬ перевод, а не отправить |
| `transfer_sbp_resolve(phone)` | **Резолвинг получателя СБП по номеру (read-only, БЕЗ денег).** Возвращает банки получателя (маскированное имя + банк + isDefaultBank + bankMemberId/pointerLinkId). ОБЯЗАТЕЛЬНО для НОВОГО (несохранённого) получателя перед комиссией/переводом |
| `payment_commission(body)` | Предпросмотр комиссии (БЕЗ денег) |
| `transfer(amount, to_account, description, provider, bank_member_id, masked_fio, pointer_link_id, from_account, force)` | Перевод (подпись внутри). phone/СБП по умолчанию; `provider="transfer-inner"` — между своими счетами. Получатель резолвится АВТО-если поля не переданы |

## Флоу

### Шаг 1: Определить тип перевода

| Пользователь сказал | Тип | `provider` |
|---|---|---|
| «переведи на +7XXXXXXXXXX» / «по СБП» | P2P по телефону (СБП) | `p2p-anybank` (по умолчанию) |
| «переведи между счетами» | Между своими счетами | `transfer-inner` |
| «переведи по реквизитам …» (БИК/счёт/ИНН) | Юр.лицо | `transfer-legal` (не автоматизировано — приложение) |

Если не указан — уточни: «Перевод по телефону (P2P) или по номеру счёта?»

### Шаг 2: Найти счёт-источник

1. Вызови `list_accounts()` — показать счета с балансами.
2. Если у пользователя один счёт с деньгами — выбери его.
3. Если несколько — спроси: «С какого счёта: Current (2751₽) или Credit (доступно 50000₽)?»
4. Запомни `account_id` источника.

### Шаг 3: Резолвинг получателя (phone/СБП — ОБЯЗАТЕЛЬНО для нового получателя)

Для перевода по телефону нужно знать банк получателя в СБП. Вызови
`transfer_sbp_resolve(phone)` (read-only, без денег):
- Вернёт по банку две строки: `И. И. | Банк ★ДЕФОЛТ`, а под ней
  `providerFields: {…}` — JSON, внутри которого и лежат `bankMemberId` и
  `pointerLinkId`. Отдельными полями в строке они НЕ печатаются, бери их из этого
  JSON.
- **Несколько банков без дефолта** — спроси пользователя, в какой банк переводить
  (перевод не в тот банк = деньги не туда). Запомни выбранные `bank_member_id` +
  `pointer_link_id` (+ `masked_fio`).
- **Пусто** — номер не зарегистрирован в СБП (или неверный). Скажи пользователю,
  перевод невозможен.
- Для **сохранённого** получателя (есть в `get_data("templates")` /
  `get_data("contacts")`) поля можно взять оттуда — резолвинг необязателен, но
  `transfer_sbp_resolve` работает всегда.

### Шаг 4: Проверить комиссию (ОБЯЗАТЕЛЬНО до перевода)

Вызови `payment_commission(body)` с `payParameters` (зеркало тела перевода — с
разрешёнными полями получателя, **не** `pointerType:ACCOUNT`, который банк отвергает):
```json
{
  "payParameters": {
    "account": "<account_id источника>",
    "moneyAmount": 1500,
    "currency": "RUB",
    "paymentType": "Transfer",
    "provider": "p2p-anybank",
    "providerFields": <providerFields из transfer_sbp_resolve — НЕ пиши pointerType/8276 руками>
  }
}
```
Получишь комиссию + описание. Покажи пользователю.

### Шаг 5: Подтверждение пользователя — ОБЯЗАТЕЛЬНО

Покажи ВСЕ данные перед переводом:
```
Перевод:
  Откуда: Current (2751 ₽)
  Куда: +7XXXXXXXXXX
  Сумма: 1500 ₽
  Комиссия: 0 ₽ (бесплатно)
  К зачислению: 1500 ₽

Подтверждаешь? (да/нет)
```

**НЕ переводи без явного подтверждения.** Если пользователь сказал «переведи» в исходной команде — это НЕ подтверждение, это запрос. Всегда показывай детали и жди «да».

### Шаг 6: Перевод

Вызови `transfer(amount, to_account, description, ...)`:
- `amount` — сумма в рублях (число)
- `to_account` — телефон (`+7XXXXXXXXXX`) для phone/СБП, либо счёт-получатель для `transfer-inner`
- `description` — сообщение получателю (он его увидит)
- **`from_account` — счёт списания из Шага 2.** Если пользователь выбирал счёт,
  передавай его обязательно: без этого аргумента спишется с первого рублёвого
  Current с положительным балансом, а не с выбранного.

**phone/СБП (по умолчанию):** если передать `bank_member_id`/`masked_fio`/`pointer_link_id`
(из Шага 3) — перевод пойдёт в выбранный банк. Если **не** передать — `transfer` резолвит
получателя автоматически и выберет дефолтный банк (или единственный); при нескольких банках
без дефолта вернёт `RECIPIENT_MULTIPLE_BANKS` со списком — тогда передай выбранные поля явно.
**Между своими счетами:** `provider="transfer-inner"`, `to_account`=счёт.
**По реквизитам юр.лица (БИК/счёт/ИНН):** пока не автоматизировано — используй приложение.

**«Перевод НЕ выполнен»** — запрос до банка не дошёл или банк его отклонил.
Деньги на месте, ничего не заблокировано: исправь причину (например, выбери банк
получателя) и повтори обычным вызовом, `force` не нужен.

**Если ответ начинается с «ИСХОД НЕИЗВЕСТЕН»** — запрос ушёл, но подтверждения нет.
Деньги могли списаться. НЕ повторяй: проверь `list_operations(from_account, days=1)`.
Перевода нет — только тогда `transfer(..., force=True)`, и он переиспользует тот же
идентификатор платежа, чтобы банк распознал повтор, а не создал второй перевод.
Повторный вызов без `force` тул заблокирует сам.

### Шаг 7: Отчёт

```
✅ Перевод выполнен
  Сумма: 1500 ₽
  Получатель: +7XXXXXXXXXX
  Комиссия: 0 ₽
  Остаток на счёте: 1251 ₽
```

При ошибке — покажи код ошибки + предложи варианты.

## Правила

1. **Всегда проверяй комиссию** перед переводом — даже если бесплатная.
2. **Всегда подтверждай** с пользователем — сумма + получатель + комиссия.
3. **Сумма — число** (1500, не "1500 рублей").
4. **Получатель** — телефон в формате `+7XXXXXXXXXX` (11 цифр, +7…) или счёт.
5. **P2P по телефону** — дефолтный вариант.
6. **Не переводи с кредитки** без явного согласия (комиссия + проценты).
