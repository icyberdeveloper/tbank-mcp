# Парковка в офисе (MyT)

Та же корпоративная сессия, что у календаря, другой сервис — `workplacer`.
Банковская сессия сюда доступа не даёт.

## Инструменты

| Тул | Что делает | Необратимо |
|---|---|---|
| `parking_places(date, building_id)` | Окно бронирования, здания, машина по умолчанию и свободные места с `place_id` | нет |
| `parking_book(date, place_id, car_number, car_model, building_id)` | **Забронировать место** | **ДА** (отменить через MCP нельзя) |
| `office_bookings(date)` | Свои брони начиная с даты: парковка, рабочее место, закреплённое место, локеры | нет |
| `myt_status()` | Жива ли сессия — проверяет живым запросом, попутно продлевает | нет |
| `myt_refresh_session()` | Обменять refresh-токен на свежий access принудительно | нет (токен не ротируется) |

## Порядок

1. `parking_places()` — без даты это **завтра**, а не сегодня: бронь открывается
   заранее, и на сегодня обычно уже поздно. Один вызов отвечает на весь вопрос —
   сколько дней вперёд открыто бронирование, во сколько открывается доступ, какие
   есть здания, на какой машине пользователь ездил в прошлый раз и какие места
   свободны.
2. `parking_book(date, place_id)` — `place_id` берётся из вывода первого шага
   (это `mapElementId`). Номер машины, марку и здание можно не передавать: они
   подставятся из прошлой брони, и тул скажет, какие именно.
3. `office_bookings()` — проверить, что уже забронировано.

## Перед бронью

Место — общий ресурс: заняв его, ты снимаешь его у коллег. Спроси:

```
Забронирую место 194 на -2 этаже, «Офис на Примерной», на 6 августа.
Машина A000AA000 (Model) — из прошлой брони. Бронируем?
```

Если пользователь приедет на другой машине, номер надо передать явно: тул по
умолчанию возьмёт прошлый, и на парковку заедет не тот автомобиль.

## Что тут неочевидно

- **200 с пустым телом — это не подтверждение.** Сервер отвечает так и на успех, и
  молча, поэтому `parking_book` после записи перечитывает брони и печатает ту
  строку, которая реально сохранилась. Читай именно её.
- **Номер машины вернётся транслитом**: `А000АА000` → `A000AA000`. Так его хранит
  workplacer, это не ошибка и не другая машина.
- **Окно бронирования короткое.** Сколько дней вперёд открыто и во сколько
  открывается доступ — называет сам `parking_places()`, оба числа приходят с
  сервера. Дата за пределами окна не пройдёт, и тул скажет, по какое число можно.
- **Пустой список мест** приходит с кодом причины. Код `2` обычно значит, что
  бронь на этот день уже есть, — проверь `office_bookings(date)`, прежде чем
  говорить «мест нет».
- **Нет доступа к парковке** — тул скажет это прямо (`hasParkingTag=false`), и
  тогда бронировать нечего, сколько ни пробуй.

## Чего тут нет

**Отменить бронь парковки нельзя** — через MCP этого нет. Не пытайся собрать запрос
сам: цена ошибки на живом корпоративном сервисе — снятая чужая бронь или молчаливый
no-op, который пользователь примет за отмену. Отправляй в приложение MyT.

Выбор конкретного места по карте этажа, бронь рабочего места и локера тоже не
выставлены — `office_bookings()` их только показывает.

## Обновление сессии

Токен продлевается **сам** перед каждым запросом, за 120 секунд до истечения:
это обмен `grantType: refresh_token` на `/v3/auth/token`. Поэтому
`токен_живёт_ещё_секунд: 0` в `myt_status()` — НЕ «сессия умерла», а всего лишь
«прошёл час с прошлого запроса»; следующий вызов её переминтит.

`myt_status()` сам делает продление и проверяет результат живым запросом, так что
его вердикт — про сервер, а не про локальные часы.

`myt_refresh_session()` запускает тот же обмен принудительно. В обычной работе он не
нужен, но полезен, когда надо проверить именно REFRESH-токен (access бывает жив, а
refresh уже отозван) или обновиться перед длинной цепочкой вызовов. Здешний
refresh-токен при обмене **не ротируется** — сервер возвращает тот же самый, так
что звать можно сколько угодно, ничего не сгорает.

Если оба тула говорят `MYT SESSION EXPIRED` — вот тогда сессия действительно мертва,
и чинится она только перелогином:

```
.venv/bin/python login_cli.py --myt <корпоративный логин>
```

Пользователь запускает это сам, в своём терминале. Тула логина нет намеренно:
корпоративный пароль не должен попадать в контекст модели. Не предлагай передать
пароль тебе.

## Правила

1. **Бронь — после явного согласия** на конкретное место и дату.
2. **Номер машины подставляется из прошлой брони** — назови его вслух при
   подтверждении, чтобы пользователь успел поправить.
3. **Отчитывайся по перечитанной броне**, а не по факту успешного вызова.
4. **Отмены нет** — не обещай её и не изображай.
