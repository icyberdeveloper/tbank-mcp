# Билеты в кино и на концерты через T-Bank MCP

MCP работает с настоящей афишей Т-Банка: бронь занимает реальные места, оплата
списывает реальные деньги. Отмена ненадёжна (см. ниже), поэтому цена ошибки здесь
выше, чем в продуктах.

## Инструменты

| Тул | Что делает | Деньги |
|---|---|---|
| `search_app(query, screen="afisha")` | Поиск по афише: кино, концерты, театр, выставки. Отдаёт `eventId` | нет |
| `cinema_search(query, city)` | Только фильмы в сегодняшнем прокате города | нет |
| `cinema_schedule(event_id, date, cinema, around, window_min, city)` | Сеансы фильма на дату. Отдаёт `slotId`, `objectId`, цену, зал. `city` — тот же, что в `cinema_search`: он задаёт и город, и точку сортировки по расстоянию (по умолчанию Москва, молча) | нет |
| `concert_schedule(event_id)` | Показы концерта: площадка, дата, `slotId`, `objectId` | нет |
| `cinema_seats(event_id, slot_id, object_id, row, max_price, kind)` | Свободные места по рядам с ценами | нет |
| `concert_hall(event_id, slot_id, object_id)` | Секторы со свободной рассадкой (входные, фан-зоны) | нет |
| `cinema_book(event_id, slot_id, object_id, seats, kind)` | **Бронь мест.** Создаёт заказ, но НЕ платит | нет |
| `ticket_pay(order_id, amount, nfs_payment_token, account_id)` | **Оплата брони** | **ДА** |
| `ticket_cancel(order_id, kind)` | Отмена заказа | нет |
| `order_details(order_id)` | Код брони, места, зал — после оплаты | нет |
| `orders("афиша")` | История заказов афиши | нет |

## Флоу

### Шаг 1: Найти событие

Фильм: `cinema_search("майкл")` или `search_app("майкл", screen="afisha")`.
Концерт/театр/выставка: только `search_app(..., screen="afisha")`.
Запомни `eventId` — он одинаков для всех городов.

Если совпадений несколько — покажи список и спроси, какое имел в виду. Не выбирай
за пользователя: «Майкл» и «Майкл Джексон. Мировое шоу» это разные вещи.

### Шаг 2: Выбрать сеанс

```
cinema_schedule("103693", "2026-07-26", cinema="каро 11", around="17:00")
```
- `date` — YYYY-MM-DD. «Завтра» считай сам от текущей даты.
- `cinema` — подстрока названия («каро 11» найдёт «Каро 11 Октябрь»).
- `around` + `window_min` — окно вокруг желаемого времени.
- `city` — если пользователь не в Москве, передай его И сюда, И в `cinema_search`.
  Умолчание молчаливое, а город задаёт ещё и точку отсчёта расстояний.

Для концертов — `concert_schedule(event_id)`, там показы не привязаны к дате.

Из ответа возьми `slotId` и `objectId` — оба нужны дальше. Покажи пользователю
варианты с ценами: цена сильно зависит от зала (880 ₽ обычный против 3300 ₽ VIP
на одном и том же сеансе).

### Шаг 3: Выбрать места

```
cinema_seats("103693", "133098547", "10255", max_price=1000)
```
- `row` — показать один ряд, `max_price` — потолок цены за место.
- Для концертов добавь `kind="concert"`.
- Если ответ пустой, а это концерт — попробуй `concert_hall(...)`: у площадки
  свободная рассадка. **Такие секторы MCP бронировать не умеет** (в захвате нет
  примера создания заказа для этого экрана) — покажи наличие и отправь в приложение.

Спроси, какие места брать, если пользователь не сказал. Середина зала ≠ первый ряд.

### Шаг 4: Забронировать

```
cinema_book("103693", "133098547", "10255", seats="7:10,7:11")
```
- Формат мест для кино — `ряд:место` через запятую.
- Для концертов — составной `seatId` из `cinema_seats(kind="concert")` **как есть**,
  вместе со всеми `|` и `§~§`.

Ответ содержит `orderId`, итоговую сумму, сервисный сбор, кэшбэк и
`nfsPaymentToken`.

> **`nfsPaymentToken` возвращается ТОЛЬКО здесь.** `order_details()` его не отдаёт.
> Потерял — оплатить эту бронь уже нельзя, придётся бронировать заново.

Деньги на этом шаге не двигаются. Неоплаченная бронь отваливается сама.

### Шаг 5: Подтвердить и оплатить

**Покажи пользователю и дождись явного «да»:**

```
Кино: Майкл, 26 июля 17:30
Место: Каро 11 Октябрь, ЗАЛ №7, ряд 7, места 10-11
Сумма: 1936 ₽ = 2 × 880 ₽ за места + 176 ₽ сервисный сбор, кэшбэк 20%
Списываю со счёта •••1234 (Black). Оплачиваю?
```

Сбор показывай отдельной строкой и не подставляй ноль: в захвате реальной
брони он был ненулевым, и именно ради него этот шаг существует — пользователь
подтверждает ИТОГ, а не цену мест.

Только после подтверждения (все три аргумента — из ответа `cinema_book`):
```
ticket_pay(order_id, 1936, nfs_payment_token)
```

> ⚠️ **«Купи билеты на Майкла» — это НЕ подтверждение оплаты.** Это запрос на
> подбор. Подтверждение — ответ на показанную сумму с конкретными местами.
> То же правило, что у `transfer` и `grocery_checkout`.

Тул сам сверяет переданную сумму с суммой заказа на бэкенде и отказывается
платить при расхождении.

### Шаг 6: Отдать код брони

После успеха — `order_details(order_id)`: код брони (`XXXXXXX`), зал, места.
Это то, что показывают на входе.

## Отмена

```
ticket_cancel(order_id)
```

> ⚠️ **Надёжность не подтверждена.** В захвате реального приложения оба пути
> отмены (`/api/order/cancel/movie` и `/api/order/cancel`) ответили 500. Если тул
> вернул ошибку — статус **НЕИЗВЕСТЕН**, а не «всё ещё забронировано». Проверь
> `orders("афиша")` и, если заказ активен, отправь пользователя отменять через
> приложение. Не вызывай отмену повторно вслепую.

## Ключевые правила

1. **Оплата — только после явного подтверждения конкретной суммы и мест.**
2. **`nfsPaymentToken` не теряй** — он есть только в ответе `cinema_book`.
3. **`slotId` и `objectId` всегда парой** — `slotId` без площадки бессмыслен.
4. **Не выбирай места и сеанс молча.** Разброс цен в одном сеансе — в разы.
5. **Свободная рассадка на концертах не бронируется** через MCP — только просмотр.
6. **После неудачной оплаты не повторяй вслепую** — сначала `orders("афиша")` и
   `order_details()`, чтобы не купить два раза.
